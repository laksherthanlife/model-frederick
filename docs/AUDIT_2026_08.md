# Audit, August 2026

A pass over the whole repository looking for defects the test suite cannot see. Everything
below was **found by running the code**, not by reading it. The suite stood at 2205 tests
when this began and passed throughout; `audit_claims.py` reported 71/71. None of it caught
any of this.

That is the finding behind the findings. A green suite says the code does what its tests
say. It says nothing about a script that cannot start, a branch that cannot move, a table
built from half its inputs, or a number in the README that stopped being true.

---

## 1. Silent degradation — three instances of one shape

A script resolves its inputs one at a time, skips what it cannot find, writes whatever it
managed to build, prints "wrote", and exits 0. The artefact is well-formed. It is smaller,
and **nothing in it says so** — its smallness is a fact about the machine that ran it.

| Where | What was lost | How it surfaced |
| --- | --- | --- |
| `make_splits.py` | 714 of 1650 manifest rows, without `YSTWIN_PLATES` | `run_heldout_score.py` died three scripts away with `'DataFrame' object has no attribute 'plate'` |
| `run_g4.py` | 2 of 3 qPCR replicates, without `YSTWIN_QPCR_RAW` | the oxidative anchor's effect became `NaN` and its replicate requirement `0` — in the table, indistinguishable from "there is no anchor" |
| `generator/design.py` | every condition, on any empty axis | a cross product with one empty factor is empty, so a sweep over **zero** conditions reported a successful run |

The third is the purest form: `context_grid(carbon_sources=())` returned `[]` and the
function's own docstring argued that "returning a smaller grid than was asked for would
hide it".

**Fixed** by `gates/artefact.py::refuse_partial_rebuild`, a bespoke guard in
`make_splits.py`, and `design.py::_axis`. The rule in all three is the same and it is
deliberately narrow: refuse only where writing would *destroy* something. A fresh clone
with no artefact builds whatever it can reach, because refusing there would strand the
first run.

## 2. A script that could not run, and a branch that could not move

`scripts/run_scenarios.py` called `latent_constraints(maintenance_per_activity=...)`. That
parameter was removed when `_MAINTENANCE_PER_ACTIVITY = 300.0` was found to be
dimensionally incoherent. **The script had been dead since that refactor.**
`tests/test_run_scenarios.py` passed 12 tests throughout — both of the ones that call
`main()` do so on the absent-model path, which exits before reaching the call.

Fixing that exposed the second half. The script handed over a synthesis rate around
`1e-3`; `latent_constraints` normalises by `_ACTIVITY_FULL_SCALE = 1305 RFU/OD/h`. The
stress fraction was about `3e-7`, the latent NGAM came out `0.7000002` against a resting
`0.7`, and the script's closing line read:

    glucose uptake shifts by -0.0% to +0.0% across scenarios

which is a sentence about units wearing the clothes of a result about biology. With the
activity kept in RFU/OD/h and the excess measured from each construct's own 0 mM rung, the
same line reads `-31.2%` at the top dose and exactly `0.0%` at the control.

Nothing asserted the branch was *capable* of differing. That is the one failure mode a
comparison script has no defence against, because its output looks like a clean negative
result.

## 3. Six stale numbers in the first table anyone reads

The README's headline table was computed at two biological replicates, before a parsing
fault that was dropping a plate was found. Every number moved:

| Sensor | Dose | README said | Actually |
| --- | --- | ---: | ---: |
| NativeYap1 | 0.1 mM H₂O₂ | 1.33 → 0.96 | 1.27 → **0.89** |
| UPRE1 | 2.0 mM DTT | 2.16 → 0.98 | 2.05 → **1.00** |
| AlteredYap1 | 1.0 mM H₂O₂ | 2.19 → 1.31 | 1.84 → **1.44** |

The AlteredYap1 row was also the wrong example. The README called it "real, but much
smaller"; its interval is [0.70, 2.86] and its verdict is INCONCLUSIVE. The row that
actually supports that sentence is UPRE2 at 1.0 mM DTT — 1.50, interval [1.21, 1.75],
DIFFERENT — and the table now carries both, side by side, because two similar-looking
folds where only one says anything is the more useful thing to show.

`FINDINGS.md`, `DATA_INVENTORY.md`, `CLAIM_BOUNDARY.md` and `ARCHITECTURE.md` all still
said "all eight rows are INCONCLUSIVE" after the third plate made six of them resolve.
`CLAIM_BOUNDARY.md` now records that it drifted, rather than being quietly corrected: a
claim boundary that drifts in the *conservative* direction is still one nobody can rely on.

**How it went unnoticed:** `audit_claims.py` pinned **10** numbers against a data cell, out
of roughly thirteen thousand in the documentation. The ten did not include the headline
table. It is now 64, and every cell of every table above is pinned, so the same drift
fails the gate rather than surviving it.

## 4. Both integrity gates were themselves wrong

- `audit_claims.py` reported any output cited as a Markdown link as **MISSING**. The
  filename pattern admits parentheses, because two committed tables carry them from the
  plate reader's own export names, so `[label](outputs/x.csv)` captured the link's closing
  paren. Fixed by paren *balance*, which is the only thing that actually separates the two
  cases.
- `audit_reproducibility.py` reported all twelve committed figures as "nobody can
  regenerate it". Two causes: `savefig` was missing from the write set, and every figure
  leaves through `fig.savefig` inside `ystwin.viz.figures` rather than in any script.
  Attribution now follows the same reachability walk the freshness check already ran, and
  resolves a destination bound to a name before the call.

A false alarm from an integrity gate is worse than a quiet one. The honest response to a
gate that cries wolf is to stop believing it.

## 5. Reproducibility was one script wide

`data/plates/` holds the four NewProtocol exports as text, because the workbooks carry a
named private individual in their document properties and cannot be committed. That made
the *measurements* reproducible by anyone who clones this. It did not make the *scripts*
reproducible: the replay lived inside `plate_readings.py` as a private shim, so one script
ran from the committed text and every other one exited on a missing `YSTWIN_PLATES` with
the numbers sitting on disk beside it.

Moved to `ystwin/plate/replay.py`. `run_calibration_nis.py`, `run_g4.py` and
`run_gates.py` now run from the committed text; each announces which source it used.
`plate_readings.py` still reproduces `sensor_characterisation.csv` to 1.8e-12 after the
move.

`run_gates.py` also had the partial-output shape, and more consequentially than the others:
it gates **two** plate sets because its finding is a comparison — the July exports are what
G1 was written against, the NewProtocol replicates are what the changed inoculation density
produced. Without `YSTWIN_PLATES` it printed "skipping the NewProtocol replicates", gated
one side, and exited 0 with a report that read as complete. A stranger now gets all five
plates instead of two.

The first attempt at that fix broke the thing it was fixing. `install` swapped the reader
for the whole module, so the July workbooks were sent to the replay too and came back "no
committed blocks". The swap is now per export, on whether the manifest covers the name --
the only thing that actually separates the two sources — and falls through to the original
reader otherwise.

Measured as a stranger would experience it, with every asset variable unset:

| Script | Before | After |
| --- | --- | --- |
| `plate_readings.py` | ran | ran |
| `run_calibration_nis.py` | exit 2 | ran |
| `run_g4.py` | exit 1 | ran |
| `run_gates.py` | ran, 2 of 5 plates, exit 0 | ran, all 5 |
| `run_d2.py` | **still needs `YSTWIN_IGEM_RESULTS`** | unchanged |

`run_d2.py` is the honest exception and stays one. It reads the two July Synergy exports,
and those are not in `data/plates` — the committed text covers the NewProtocol set and the
BY4741 control, which is what the manifest lists. There is no replay to give it. Saying so
is the fix available today; committing the July exports is not, for the same reason the
others are not committed.

## 6. Dead public surface

Six public callables had never been executed by anything — not a script, not a test:
`admission_status`, `FluxSurrogate.input_names`, `Condition.quadrant`,
`EnvironmentCondition.quadrant`, `PanelFamily.describe`, `LossPartition.total_at_interval`.

Five were a pass-through alias, an accessor and three display strings, and were deleted.
The sixth is a real formula, and the interesting part is *why* it was dead:
`tests/test_kdeg_calibration.py` hand-copied `k_deg + bleach_per_read / dt` inline to build
its fixture rather than calling the method. Two copies of one formula, one of them never
run. It is now exercised by the test that matters — fit on two read intervals, predict a
third it never saw.

## 7. Oxygen had no ceiling

`CultureContext` bounded `oxygen` below at 0.0 and not above. A gas-phase mole fraction of
2.0 was accepted, and — because the aeration term saturates at air — returned exactly the
air answer. So did 1.0, which is a real condition: pure-O₂ sparging raises ROS and the
oxidative burden the stress panel exists to carry.

A sweep dialling oxygen up would have seen a flat line and read it as evidence that
enrichment is inert. Above 1.0 is now refused as not-a-fraction; between air and 1.0 is
refused as unmodelled, with the reason stated.

## The thiolase lead is weaker than it was reported

Two separate defects, and together they cost the lead its strongest form.

`scripts/thiolase_threshold.py` printed its cofactor grid — ending in a row reading
`300u 3.0u 663.3u below below`, ethanol **below** — and then printed:

> *"Glucose stays below and ethanol stays above across the whole grid, which is the claim."*

False against its own output, in the same terminal scroll. The tests
(`test_it_survives_most_of_the_cofactor_grid_but_not_all_of_it`, asserting `held == 8`) and
`DISTANCE_TO_THE_VISION.md` ("holds 8 of 9") were already right; the prose was the stale one,
and `thermo_gate.py` pointed readers at that script "for the provenance and the caveats".

Worse, and nobody had run it: the volume table was computed at **one** cofactor pair and the
cofactor grid at **one** volume. Crossing them:

```
    volume   ethanol      [CoA]=30u   [CoA]=100u   [CoA]=300u
       1.0     850uM          ABOVE        ABOVE        ABOVE
       2.0     425uM          ABOVE        ABOVE        ABOVE
       2.7     315uM          ABOVE        ABOVE        below   <-- FLIPS
```

2.7 mL/gDW and 300 µM CoA are **both inside** the ranges the repository itself calls
plausible. So the honest claim is: the ordering is robust to either convention alone and
**not to their cross product**. The glucose side remains robust — it would need [CoA] near
0.2 µM to clear.

## Item 1 is NOT closed

`pathway/thermo_gate.py` is imported by **nothing outside its own tests**. `predict.py` does
not call it, so no prediction is gated by it today. And the join it exists to make is not
exercised on real chemistry anywhere: on the synthetic chain a solved pool does reach Q but
the energies are invented, and on `phb` — the only real-energy pathway gated — both
thioesters are `passthrough`, solve to exactly zero, and acetyl-CoA is not a node, so
**every concentration in that verdict comes from `background_m`**. A seam was built, not a
join. `DISTANCE_TO_THE_VISION.md` now says so.

## The nan defect was three sites, not three sites

The previous pass found that `slim_optimize()` signals failure with **nan, not None**, and
fixed three call sites in `fba/`. This pass found **seven more still live**, in `bridge/` and
`scripts/` — one of them observed printing `max growth nan /h  (  nan% of max)` from
`scripts/parked/run_d1.py` during this session's regeneration.

Every one failed **open**:

| Site | Expression | What nan does |
| --- | --- | --- |
| `bridge/tmfa.py:140` | `slim_optimize() or 0.0` | nan is truthy → nan. A fallback that never falls back |
| `bridge/physiology_bridge.py:158` | `growth < lower - 1e-6` | False → a model that cannot support the measured rate passes |
| `bridge/regulation.py:647` | `growth <= 0.0` | False → **`InfeasibleRegulation` could never raise**, which is that check's entire purpose |
| `bridge/regulation.py:775` | `maximum <= 0.0` | False → a task with no maximum passes |
| `bridge/regulation.py:837` | `0.0 if growth is None` | nan reported as `max_growth` |
| `scripts/run_regulation.py:99` | `maximum * growth_fraction` | nan becomes a biomass lower bound, which FVA accepts and answers around |
| `scripts/parked/run_d1.py:88` | `"infeasible" if g is None` | dead branch; prints `nan` |

All seven now call `growth_or_none`. `tests/test_no_unguarded_slim_optimize.py` scans every
file in `src/` and `scripts/` (116 of them) and fails on any raw read without a nearby
`isnan` — verified to fail when one is reintroduced. A fix in one module does not hold a
codebase; the grep does.

One more, caught by review of this pass's own fix: the new refusal in `run_regulation.py`
interpolated `{label!r}`, which is **not in that function's scope** — it would have raised
`NameError` instead of the message. Corrected before commit.
